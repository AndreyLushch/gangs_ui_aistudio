# Gangs — Игра в стиле Мафии (Telegram Mini App)

Веб-приложение игры «Gangs» для живой компании 4–25 человек в одной комнате без ведущего.

## 1. Архитектура проекта и разделение слоёв

- `src/config/gameConfig.ts` — единый конфигурационный объект `GAME_CONFIG`, формулы, таблицы составов ролей и диапазоны N.
- `src/types/game.ts` — строгая типизация состояния (`GameState`), ролей, зон Общественного мнения и клиентской проекции (`PlayerView`).
- `src/strings/ru.ts` — все русскоязычные тексты, системные сообщения, шаблоны анонимных записок и описания ролей.
- `src/utils/haptics.ts` — безопасная обёртка для `Telegram.WebApp.HapticFeedback` и `navigator.vibrate`.
- `src/engine/` — чистая логика конечного автомата игры без зависимостей от React:
  - `calculations.ts` — алгоритмы похищения ночью (с весом Босса 1.5 и защитой Стража/Мстителя), утренних проверок Шерифа и Босса, Общественного мнения (давление, инерция, шум, всплески, зоны) и судебного голосования (вес Судьи 1.5, оправдание Адвокатом).
  - `stateMachine.ts` — переходы фаз, действия игроков, автозаполнение ботов и функция `getPlayerView(state, playerId)`, фильтрующая скрытые роли других игроков.
  - `engine.test.ts` — автоматические модульные тесты (`node:test`).
- `src/components/` — переиспользуемые UI-компоненты:
  - `Ranker.tsx` — единый интерфейс ранжирования подозрений для ночи и суда (гарантирует неразличимость ролей по поведению в телефоне).
  - `RoleCard.tsx` — карточка роли на `ROLE_CARD_TTL` (только арт + имя роли, без описания).
  - `ZoneBadge.tsx` — доступные значки зон Общественного мнения (цвет + иконка + форма).
  - `SideCounter.tsx` — постоянный счётчик живых горожан и гангстеров.
  - `PhaseTimer.tsx` — таймер фазы с подсветкой срочности.
  - `NoteSheet.tsx` — отправка анонимных записок с шаблонами.
  - `RulesModal.tsx` — правила игры и расшифровка спецролей.
  - `DevPanel.tsx` — выдвижная панель симуляции для переключения взгляда между игроками, автозаполнения ботов и управления фазами.
- `src/views/` — экраны для каждой фазы (Lobby, Day 0, Night, 3-шаговое утро, День-обсуждение, Суд, Финал).

## 2. Как заменить мок-движок на сервер по WebSocket

Интерфейс UI полностью изолирован от внутреннего состояния и работает исключительно с проекцией `PlayerView`:
1. В `src/App.tsx` заменить локальный `useState<GameState>` на хук `useGameSocket()`:
   ```ts
   const { playerView, dispatchAction } = useGameSocket(roomId, myPlayerId);
   ```
2. Сервер (Node.js/Bun/Go) реализует те же функции из `src/engine/stateMachine.ts` и `src/engine/calculations.ts`.
3. При каждом событии сервер отправляет каждому клиенту индивидуальное сообщение `PLAYER_VIEW_UPDATE` с результатом `getPlayerView(state, clientPlayerId)`.
4. Клиент отправляет действия (`SUBMIT_RANKING`, `SEND_NOTE`, `TOGGLE_READY`, `ADVANCE_PHASE`). Ни один компонент UI переписывать не требуется.

## 3. Список мест с `// TODO(spec)` по нерешённым вопросам спецификации

1. **Значения таймеров фаз** (`src/config/gameConfig.ts`):
   - `DAY_0_TIMER: 120` сек
   - `NIGHT_TIMER: 45` сек
   - `DISCUSSION_TIMER: 180` сек
   - `VOTING_TIMER: 45` сек
   *Статус:* не утверждены в спецификации, вынесены в `GAME_CONFIG` для последующей настройки из админки.

2. **Политика незавершённого ранжирования** (`PARTIAL_RANKING_POLICY`):
   - По умолчанию `'partial'` (учитывать частично расставленных игроков).
   - Альтернатива `'neutral'` (заполнять оставшиеся слоты нейтральным весом).
   *Помечено в коде:* `src/config/gameConfig.ts` и `src/engine/calculations.ts`.

3. **Режим наблюдателя для выбывших игроков** (`SPECTATOR_MODE`):
   - По умолчанию `true`: выбывшие видят счётчик сторон, фазы и исходы, но не имеют доступа к запискам и скрытым данным.
   *Помечено в коде:* `src/config/gameConfig.ts` и `src/App.tsx`.
